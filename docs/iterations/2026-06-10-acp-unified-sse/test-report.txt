8. First deployment attempt

Command:

```text
./scripts/deploy.sh
```

Result: INTERRUPTED

Observed output:

```text
npm error code ECONNRESET
npm error network Client network socket disconnected before secure TLS connection was established
agent runtime npm install attempt 1 failed; retrying in 10s...
```

Diagnosis:

- Wrangler builds the container as `linux/amd64` on this `arm64` host, so npm runs through `qemu-x86_64`.
- The npm install process was still CPU-active, not deadlocked.
- The Dockerfile retry loop had a correctness bug: if all five npm attempts failed, the shell loop could exit successfully because the final command was `sleep`. That could produce a container image missing the agent runtime.

Fix applied:

- Split `@anthropic-ai/claude-code` and `@agentclientprotocol/claude-agent-acp` into separate install layers.
- Added explicit `exit 1` after five failed attempts.
- Added `claude --version` and `claude-agent-acp --cli --version` build-time verification.
- Added npm fetch timeout/retry maximums.

10. Second deployment attempt

Command:

```text
./scripts/deploy.sh
```

Result: BLOCKED BY LOCAL CONTAINER BUILD

Observed output:

```text
#8 added 2 packages in 5m
#8 2.1.148 (Claude Code)
#9 npm error code ECONNRESET
#9 npm error network Client network socket disconnected before secure TLS connection was established
#9 claude-agent-acp npm install attempt 1 failed; retrying in 10s...
```

Additional checks:

```text
ps -eo pid,ppid,pcpu,pmem,etime,cmd | rg "claude-agent-acp|npm install -g|qemu-x86_64"
curl -I --max-time 20 https://registry.npmjs.org/@agentclientprotocol/claude-agent-acp/-/claude-agent-acp-0.43.0.tgz
```

Findings:

- The host is `linux/arm64`.
- Wrangler/Docker builds the Cloudflare container as `linux/amd64`.
- The npm install process runs under `/usr/bin/qemu-x86_64`.
- The qemu npm process remained CPU-active for about 18 minutes, then hit `ECONNRESET`.
- Host-level `curl` to the same npm tarball returned HTTP 200 immediately, so the machine's outbound network was not generally down.
- Cloudflare Containers currently require images that can run on `linux/amd64`, so an ARM-only production image is not a valid target.

Conclusion:

- Deployment is blocked by the local cross-architecture container build path, not by the ACP/SSE code changes.
- The right fix is to build the Cloudflare container on an amd64 builder or prebuild/cache an amd64 image. Continuing qemu npm retries on this host is slow and unreliable.
